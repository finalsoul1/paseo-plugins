# 에이전트 기록 필터

## 배경

Paseo 기본 「기록」 화면에는 필터가 없어서, 쌓인 에이전트(2026-10-28 기준 555개, 그중 534개 아카이브)에서 원하는 것을 찾으려면 스크롤하거나 제목을 기억해야 한다. 플러그인 API로는 기본 「기록」 화면에 UI를 끼워 넣을 수 없으므로, 필터가 있는 기록 화면을 플러그인 화면으로 따로 만든다.

## 범위

포함

- 플러그인 화면 하나: 에이전트 기록 목록과 필터.
- 화면 진입점: 사이드바 헤더 항목과 ⌘K 항목.
- 행을 누르면 그 에이전트를 연다(`navigation.openAgent`).

제외

- 업무 이슈 단위로 묶기. 별도 플러그인에서 한다.
- 아카이브 해제, 삭제, 이름 바꾸기 같은 에이전트 조작. 기본 화면에서 한다.
- 필터 조건 저장. 화면을 다시 열면 기본값으로 돌아간다.
- 화면 밖에서 이 화면을 여는 단축키. 진입점은 사이드바와 ⌘K다.

## 데이터

- 클라이언트에서 `paseo.agents.list({ filter: { includeArchived: true }, sort: [{ key: "updated_at", direction: "desc" }], page: { limit: 200 } })`를 `nextCursor`가 없을 때까지 반복해 전부 받는다. `page.limit`은 200이 최대다. 실측: 555개, 3페이지, 약 0.2초.
- `fetch_agents_request`는 `filter`(`projectKeys`, `statuses`, `includeArchived`, `requiresAttention`, `labels`, `thinkingOptionId`), `sort`, `page`를 받지만 `search`는 없다. 플러그인 SDK(`PaseoApi`)에는 `fetch_agent_history_request`를 부르는 메서드가 없다. 그래서 검색과 필터는 받아 둔 목록으로 클라이언트에서 계산한다. 필터를 바꿀 때마다 다시 묻지 않아서 항목 옆 건수도 바로 셀 수 있다.
- 데몬 호출이라 플러그인 RPC와 서버 엔트리는 쓰지 않는다.
- 화면을 열 때 한 번 받고, 새로고침 버튼으로 다시 받는다. 실시간 구독은 하지 않는다.

## 화면 구성

- 넓은 화면: 왼쪽 칸(220px)에 검색과 필터, 오른쪽에 제목·건수·새로고침과 목록. 좁은 화면: 목록 위에 검색과 필터 칩 줄.
- 행은 두 줄이다. 첫 줄은 상태 점, 제목(없으면 `제목 없음`), 확인 필요 표시, 마지막 갱신 시각(`3분 전`, `10/27`)이다. 둘째 줄은 상태, 프로젝트 이름, 브랜치(없으면 워크스페이스 이름), 프로바이더, `아카이브`를 흐린 글자로 잇는다. 아카이브된 행은 제목도 흐린 색으로 둔다.
- 목록은 100개까지만 그리고, 나머지는 "더 보기 (N개 남음)"으로 100개씩 늘린다. 필터나 정렬을 바꾸면 다시 100개부터다.
- 값이 하나뿐인 체크박스 그룹은 고를 것이 없어서 숨긴다. 보관, 기간, 확인 필요는 늘 보인다.
- 적용된 조건은 목록 바로 위에 라벨로 보여주고, 라벨을 누르면 그 조건만, "모두 지우기"를 누르면 정렬을 뺀 모든 조건이 풀린다. 좁은 화면에서는 이 줄 앞에 필터 줄과 같은 64px 열로 「적용됨」을 붙인다.
- 간격은 `paseo-ui-kit`의 `SPACE`에 있는 4·8 배수 값(4, 8, 12, 16, 24)에서만 고른다. 좁은 화면에서 필터 줄끼리는 8, 필터 블록과 「적용 조건 + 목록」 사이는 24, 칩이 줄바꿈될 때 위아래는 4다. 넓은 화면의 왼쪽 칸은 항목끼리 4, 그룹 제목과 첫 항목은 8, 그룹끼리는 16이다. 왼쪽 칸은 스크롤바를 보이지 않는다(창이 낮으면 휠로는 스크롤된다).
- 정렬 세그먼트, 필터 칩, 적용 조건 라벨은 높이를 26으로 맞춘다.
- 정렬: 최근 갱신순(기본), 생성순, 제목순.

## 필터

| 그룹 | 값 | 기준 필드 | 기본값 |
| --- | --- | --- | --- |
| 검색 | 자유 입력 | `title`, `project.projectName`, `project.workspaceName`, `checkout.currentBranch`, `cwd` 부분 일치(대소문자 무시) | 비어 있음 |
| 보관 | 활성만 / 아카이브만 / 전체 | `archivedAt` | 아카이브만 |
| 상태 | 실행 중, 대기, 오류, 종료, 시작 중 | `status` (`running`, `idle`, `error`, `closed`, `initializing`) | 선택 없음 |
| 확인 필요 | 켬/끔 | `requiresAttention` | 끔 |
| 프로젝트 | 받은 목록에 있는 프로젝트 | `project.projectKey` | 선택 없음 |
| 프로바이더 | 받은 목록에 있는 프로바이더 | `provider` | 선택 없음 |
| 출처 | 직접 만듦 / 스케줄 실행 / 하위 에이전트 | `labels`의 `paseo.schedule-id`, `paseo.parent-agent-id` | 선택 없음 |
| 기간 | 오늘 / 최근 7일 / 최근 30일 / 전체 | `updatedAt` | 오늘 |

- 기본값으로 걸린 보관·기간 조건도 적용된 조건 라벨로 보인다. "모두 지우기"는 기본값이 아니라 조건이 하나도 없는 상태(보관·기간 「전체」)로 되돌린다.
- 같은 그룹 안은 OR, 그룹끼리와 검색어는 AND로 묶는다.
- 항목 옆 건수는 지금 조건에 그 항목을 더하면 몇 건인지다. 같은 그룹의 선택은 계산에서 뺀다. 0건 항목은 숨기지 않고 흐리게 둔다.

- 프로젝트와 프로바이더 항목은 받은 목록에 있는 값만, 많이 쓴 순서로 둔다.

## 단축키

모두 웹(데스크톱)에서만 동작한다.

- 화면을 열면 검색창에 포커스가 간다. 네이티브는 키보드가 목록을 가려서 하지 않는다.
- ⌘L은 이 화면이 보일 때만 검색창으로 포커스를 옮긴다. 다른 화면에서는 Paseo의 원래 동작(메시지 입력창 포커스)을 그대로 둔다. 검색창이 비어 있고 포커스가 없을 때 오른쪽에 `⌘L` 안내를 흐리게 보여준다.
- 검색창에서 아래 화살표나 Enter를 누르면 첫 행으로 간다. Esc는 입력값이 있으면 지우고, 비어 있으면 포커스를 뺀다.
- 행에서는 위·아래 화살표, Home, End로 옮겨 다니고, 첫 행에서 위 화살표나 Esc를 누르면 검색창으로 간다. Enter는 그 에이전트를 연다. Tab은 목록 전체를 한 번에 건너뛴다.
- 검색창과 행 밖에서 Esc를 누르면 열기 전 화면으로 돌아간다. ⌘K나 대화상자가 열려 있으면 그쪽이 받는다.

코드: `paseo-ui-kit/src/web.ts`

## 결정

- 2026-10-28 사용자 확인: 필터는 위 표 전부를 넣는다. 진입점은 사이드바 헤더 항목과 ⌘K이고, 슬래시 명령과 화면을 여는 단축키는 넣지 않는다.
- 2026-10-28 사용자 요청: 보관 기본값을 「전체」에서 「아카이브만」으로, 기간 기본값을 「전체」에서 「오늘」로 바꾸고, 화면 안 단축키와 검색창 포커스를 다른 목록 화면 플러그인과 같게 단다.
- 2026-10-29 사용자 요청: 게슈탈트 리뷰 제안 4건(필터 블록과 목록 사이 간격, 적용 조건 줄의 「적용됨」 라벨, 정렬·칩 높이 통일, 간격 스케일 상수화)을 반영한다.
- 2026-10-29 사용자 요청: 넓은 화면 왼쪽 칸에 스크롤이 겨우 생기는 문제를 없앤다. 그룹 간격을 24에서 16으로 줄이고 스크롤바를 숨긴다. 16도 그룹 안 간격(4, 8)보다 넓어서 묶음은 그대로 보인다.
- 2026-10-29 사용자 요청: 다른 플러그인과 모양이 같은 공통 UI를 `../paseo-ui-kit` 로컬 패키지로 분리해 같이 쓴다.

- [ ] 위 단축키가 적혀 있는 대로 동작하고, 다른 화면에서 ⌘L은 메시지 입력창으로 간다.
