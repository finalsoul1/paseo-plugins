# 판단 대기

## 배경

에이전트를 여러 개 동시에 돌리면 어느 에이전트가 내 답을 기다리는지 기억해 두기 어렵다. Paseo 사이드바의 상태 점은 "아직 열어 보지 않음"(`requiresAttention`)만 보여 주므로, 결과를 한 번 열어 보면 점이 꺼진다. 그런데 열어 본 뒤 답을 미뤄 둔 에이전트가 많다. 이런 에이전트는 아직 내 판단을 기다리는데도 사이드바에서는 끝난 작업과 구분되지 않는다.

또 무엇을 기다리는지 보려면 워크스페이스에 들어가 대화를 읽어야 한다. 에이전트가 요청하는 내용은 대개 마지막 메시지의 마지막 문단에 있다(2026-11-09 실측: 활성 에이전트 17개 중 요청이 있는 메시지는 모두 마지막 문단에 "알려 주세요", "정해 주세요", "확인이 필요합니다" 같은 문장이 있었다).

## 목표

내 답을 기다리는 에이전트를 한 화면에 모으고, 각 행에서 무엇을 기다리는지 한두 줄로 보여 준다. 열어 본 것도 답하거나 아카이브하기 전까지 목록에 남는다.

## 판정 규칙

아래를 모두 만족하는 에이전트를 「판단 대기」로 본다.

- 아카이브되지 않았다(`archivedAt`이 없다).
- 지금 실행 중이 아니다(`status`가 `running`이 아니다).
- 대화의 마지막 메시지가 어시스턴트 메시지다. 내가 마지막으로 말했으면 공은 에이전트에게 있으므로 뺀다.

예외 두 가지는 실행 상태와 마지막 메시지를 보지 않고 넣는다.

- 권한 요청(`pendingPermissions`)이 있다. 권한을 기다리는 동안 `status`는 `running`이고 대화의 마지막 항목은 `tool_call`이라서 위 규칙으로는 잡히지 않는다(2026-11-09 실측).
- `status`가 `error`다. 답을 만들기 전에 실패하면 마지막 메시지가 내 메시지로 남는다. `lastError`만 있고 `status`가 `error`가 아니면 위 규칙을 그대로 따른다.

내용을 보고 질문인지 판단하지 않는다. `?`로 끝나는지 보는 방식은 실측에서 요청 17건 중 1건만 잡았고, "알려 주세요" 같은 문구 목록은 계속 새 표현이 나와 유지할 수 없다. 대신 "아카이브 = 내가 끝냈다"는 사용 습관에 기대고, 할 일이 없는 에이전트는 사용자가 아카이브해서 목록에서 뺀다.

## 범위

포함

- 사이드바 헤더 항목. 건수가 있는 묶음마다 행 하나(「권한 요청 1」, 「새 결과 5」 등)를 두고, 누르면 판단 대기 화면의 그 묶음 위치로 연다.
- 판단 대기 화면. 기록 화면과 같은 행 구조(누르면 아래로 대화 미리보기, 「열기」 버튼)를 쓰고, 행마다 요약 줄을 더한다.
- 행 분류와 정렬(아래 「화면 구성」).

제외

- 화면 안에서 바로 답하기. 답은 에이전트를 열어서 한다.
- 질문 여부를 내용으로 판단하기(위 「판정 규칙」 참고).
- 동시에 진행하는 에이전트 수 제한이나 경고.
- 기존 기록 화면의 필터와 행 표시 변경.

## 데이터

- 목록: `paseo.agents.list({ includeArchived: false, subscribe: {} })`로 받고 구독으로 갱신한다. 상태가 바뀌면 사이드바 숫자와 화면이 바로 바뀌어야 하므로 기록 화면처럼 30초 캐시에 기대지 않는다. 구독이 안 되면 그 이유를 스펙에 적고 주기적으로 다시 받는다. 2026-11-09 실측으로 구독은 된다. 처음에 스냅숏이 오고, 이후 `agent_update`(`upsert`, `remove`)가 오며, 아카이브하면 `remove`가 온다.
- 마지막 메시지: 실행 중이 아닌 활성 에이전트마다 `timeline.refetch({ direction: "tail", limit: 200, projection: "projected" })`로 받는다. 기록 화면 미리보기와 같은 React Query 키를 써서 행을 펼칠 때 다시 받지 않게 한다. 에이전트의 `updatedAt`이 바뀌었을 때만 다시 받는다.
- 2026-11-09 실측(활성 22개): 한 번 받는 데 1~370ms였다. 워크트리 폴더가 지워진 에이전트는 `refetch`가 `Working directory does not exist` 예외를 던졌다. 예외는 에이전트별로 잡아서 그 행만 「대화를 불러오지 못함」으로 두고 나머지는 계속 보여 준다.
- antigravity 에이전트는 `refetch`가 프로세스를 띄우다 실패해 4초 넘게 걸린다(기록 화면 미리보기 스펙의 실측). 자동으로 받지 않고, 판단 대기 판정에서도 뺀다.

## 화면 구성

- 묶음과 순서. 묶음 안에서는 오래 기다린 것이 위다(마지막 어시스턴트 메시지 시각 기준).
  1. 권한 요청: `pendingPermissions`가 있다. 요약 줄은 요청의 `title`(없으면 `name`)이다.
  2. 오류: `status`가 `error`이거나 `lastError`가 있다. 요약 줄은 오류 문구다.
  3. 새 결과: `requiresAttention`이 참이다.
  4. 확인함: 나머지. 열어 봤지만 아직 답하지 않은 것이다.
- 행 첫 줄은 기록 화면과 같다(상태 점, 제목, 시각). 둘째 줄은 요약 줄이다. 권한 요청과 오류가 아니면 마지막 어시스턴트 메시지의 마지막 문단을 마크다운 기호를 빼고 두 줄까지 보여 준다. 첫 문단이 아니라 마지막 문단을 쓰는 이유는 요청이 그곳에 있기 때문이다.
- 셋째 줄에 프로젝트 이름과 브랜치를 흐린 글자로 둔다.
- 빈 목록: 「기다리는 에이전트가 없습니다.」
- 사이드바는 건수가 있는 묶음만 화면과 같은 순서로 한 행씩 보여 준다. 행 이름이 묶음 이름이라 숫자가 무엇을 센 것인지 바로 읽힌다. 숫자 색은 권한 요청·새 결과가 경고색, 오류가 위험색, 확인함이 흐린 색이다. 기다리는 에이전트가 없거나 목록을 받는 중이면 「판단 대기」 행 하나만 둔다.
- 사이드바 행은 화면을 `params.group`과 함께 열고, 화면은 그 묶음 위치로 스크롤한다.

## 완료 기준

- [x] 판정 규칙에 맞는 에이전트 수가 데몬 원본 응답으로 따로 센 값과 같다. 2026-11-09 실측: 활성 21개 중 플러그인 코드(`awaiting.ts`, `queries.ts`의 `toActiveAgent`·`fetchPreview`를 esbuild로 묶어 Node에서 실행) 19개, 원본 응답으로 센 값 19개, 에이전트 id도 같았다. 묶음은 권한 요청 1, 새 결과 5, 확인함 13이었다.
- [x] 결과를 열어 본 에이전트가 「새 결과」에서 「확인함」으로 옮겨 가고, 목록에서 빠지지 않는다. 앱에서 화면을 여는 대신 `clearAgentAttention`으로 확인 표시를 지웠고, 구독 업데이트 한 번에 `new`에서 `seen`으로 옮겨 갔다. 전체 수는 19로 그대로였다.
- [x] 에이전트에 답을 보내면 목록에서 빠지고, 턴이 끝나면 다시 들어온다. 답을 보내자 `running`이 되면서 19에서 18로 줄었고, 2초 뒤 턴이 끝나자 19로 돌아왔다. 요약 줄도 새 답으로 바뀌었다.
- [x] 아카이브하면 목록에서 빠진다. 구독으로 `remove`가 와서 19에서 18로 줄었다.
- [x] 워크트리가 지워진 에이전트가 있어도 화면이 뜨고, 그 행만 오류 문구를 보여 준다. 실제 앱에서 2개 행만 「대화를 불러오지 못함: Working directory does not exist: ...」를 보여 주고 나머지 17개 행은 요약 줄이 정상으로 나왔다.
- [x] 요약 줄이 실제 마지막 문단과 같다. 표본 5개 모두 원문의 마지막 문단에서 마크다운 기호(`**`, 목록 기호)만 빠진 문장과 같았다. 그중 1개는 마지막 문단이 링크 목록뿐이라 요약 줄에 URL만 나왔다. 규칙대로 동작한 결과라 고치지 않았다.
- [x] `npm run typecheck`, 모바일 호환 audit을 통과하고 플러그인이 `running`이다.
- [x] 사이드바가 건수가 있는 묶음만 행으로 보여 준다. 2026-11-10 앱에서 「새 결과 2」(경고색)와 「확인함 19」(흐린 색) 두 행을 확인했다. 그때 없던 권한 요청·오류 행의 아이콘 이름(`ShieldAlert`, `CircleAlert`)은 앱 번들에 있는 것까지만 확인했다.
- [ ] 사이드바 묶음 행을 누르면 판단 대기 화면이 그 묶음 위치로 열린다. 사용자가 앱을 쓰는 중이라 클릭으로 확인하지 않았다.

실제 앱 확인 방법: 설치된 플러그인은 메인 checkout 경로에서 로드되므로, 워크트리 디렉터리를 `paseo plugin install <워크트리>/paseo-agent-history --id paseo-agent-history-dev`로 따로 설치해 확인했다. 앱에서는 사이드바(그때는 합계 하나만 보여 주던 「판단 대기 19」), 화면의 묶음·요약 줄·오류 행, 권한을 허용한 에이전트가 「권한 요청」에서 「새 결과」로 옮겨 가는 것까지 봤다. 그 뒤 단계(열어 보기, 답 보내기, 아카이브)는 사용자가 앱을 쓰고 있어 클릭을 멈추고, 같은 구독과 판정 코드를 Node에서 돌려 확인했다.
