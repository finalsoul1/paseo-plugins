# HTML 뷰어 검색

## 배경

Paseo 내장 HTML 뷰어(0.17.4 `FileHtmlPreview`)는 HTML을 `data:` URL로 바꿔 `sandbox="allow-scripts"` iframe에 넣기만 하고 검색 UI가 없다. 앱의 `Find in pane` 검색 바(`PaneFind`)는 코드 편집기, 에이전트 대화, 터미널에만 붙어 있다. iframe에 `allow-same-origin`이 없어서 바깥 화면은 iframe 안의 DOM을 읽을 수 없고, 그래서 기존 검색 바를 그대로 붙일 수도 없다.

보고서처럼 긴 HTML 문서를 Paseo 안에서 열어 둘 때 특정 문구를 찾으려면 지금은 브라우저로 따로 열어야 한다.

## 방식

`addFilePanel`로 `.html`·`.htm` 파일 패널을 추가한다. Paseo는 같은 확장자에 패널이 여럿이면 「Open .html files with」 선택 화면을 띄우고, 「Always use for .html」로 기본값을 정할 수 있다. 내장 뷰어는 그대로 남는다.

- 파일 내용은 `useFileText`로 읽는다. 파일이 디스크에서 바뀌면 다시 렌더링한다.
- HTML 앞에 내장 뷰어와 같은 CSP(`connect-src 'none'` 등)와 검색용 스크립트를 넣어 `sandbox="allow-scripts"` iframe의 `srcdoc`으로 렌더링한다. `allow-same-origin`은 주지 않는다. 주면 HTML 파일의 스크립트가 Paseo 앱의 DOM과 저장소에 접근할 수 있다.
- 검색 바는 iframe 바깥에 React Native로 그리고, 테마 색을 따른다. 검색어와 이동 명령은 `postMessage`로 iframe에 보내고, 넣어 둔 스크립트가 일치 개수와 현재 위치를 돌려준다. 메시지는 `event.source`가 이 패널의 iframe일 때만 받는다.
- 일치한 부분은 CSS Custom Highlight API로 표시한다. 문서 DOM을 고치지 않으므로 HTML 파일의 스크립트와 충돌하지 않는다.
- iframe·DOM 접근은 `client/web.ts`에만 둔다. 웹이 아닌 클라이언트(모바일)에서는 SDK의 `DocumentFrame`으로 검색 없이 보여 준다.

## 동작

- ⌘F(Windows·Linux는 Ctrl+F)로 검색 바를 열고 입력칸에 포커스한다. 포커스가 이 패널 안(iframe 포함)에 있을 때만 가로챈다. iframe 안에서 누른 ⌘F는 넣어 둔 스크립트가 바깥으로 전달한다.
- 입력하는 즉시 찾는다. 대소문자는 구분하지 않는다.
- Enter는 다음, Shift+Enter는 이전으로 이동하고 끝에서 처음으로 돈다. 현재 일치 위치로 스크롤하고 다른 색으로 표시한다.
- 검색 바에 `3/12`처럼 현재 위치와 전체 개수를, 없으면 「결과 없음」을 보여 준다.
- Esc나 닫기 버튼으로 검색 바를 닫으면 표시를 지운다.
- 파일이 바뀌어 다시 렌더링되면 열려 있던 검색어로 다시 찾는다.

## 범위 밖

- 바꾸기
- 내장 HTML 뷰어 자체를 고치는 것

## 완료 기준

2026-11-24 찾기 스크립트 실측은 `buildDocument` 결과를 `sandbox="allow-scripts"` iframe의 `srcdoc`에 넣은 시험 페이지를 Chromium(Paseo 브라우저, Playwright)에서 열고 `postMessage`로 검색해 확인했다. 시험 문서에는 인라인 경계(`<b>tar</b>get`), 블록 경계(`<div>tar</div><div>get</div>`), `display:none`·`visibility:hidden` 문단, `document.write`와 load 직전 스크립트로 넣은 글자, 문단 80개를 넣었다.

- [ ] `.html` 파일을 열 때 선택 화면에 이 패널이 나오고, 고르면 내장 뷰어와 같은 모양으로 렌더링된다.
- [ ] ⌘F로 검색 바가 열린다.
- [x] 검색어 입력 시 일치 개수가 실제 문서 텍스트에서 센 값과 같다. 실측: `TaRgEt` 12건(기대값 12, 인라인 경계 포함·블록 경계와 숨긴 문단 제외·스크립트로 넣은 글자 포함), `문단 7` 11건(기대값 11).
- [x] 다음·이전으로 이동하면 해당 위치로 스크롤되고 위치가 바뀐다. 끝에서 처음으로 돈다. 실측: 0에서 이전 두 번이면 11, 마지막 결과(문단 70)가 iframe 가운데로 스크롤됨. 현재 결과는 주황, 나머지는 노랑으로 표시됨.
- [x] 다시 렌더링한 뒤 보던 순번으로 다시 찾는다. 실측: `index: 9`로 검색하면 `current` 9.
- [ ] 찾기 바의 Enter·Shift+Enter, 위치 표시, 한글 조합 중 Enter.
- [ ] iframe 안을 클릭한 뒤 누른 ⌘F도 검색 바를 연다. 다른 pane에 포커스가 있을 때는 가로채지 않는다.
- [ ] Esc로 닫으면 표시가 사라진다.
- [ ] 파일을 고치면 다시 렌더링되고 검색 결과가 갱신된다.
- [ ] 라이트·다크 테마에서 검색 바 글자가 읽힌다.
- [x] `npm run typecheck` 통과, 설치 후 `running`(2026-11-24).

체크하지 않은 항목은 앱 화면에서 확인해야 한다. 데몬이 Origin이 다른 브라우저 접속을 403으로 막아서, 앱 웹 빌드를 브라우저로 띄워 자동으로 확인하는 방법은 쓰지 못했다.
